비콘 출결 · 운영 중 발생

실시간 기능 배포 후 전체 API 중단

증상
관리자용 실시간 출석 현황을 배포한 뒤 모든 API가 한꺼번에 멈췄습니다. 혼자 테스트할 때는 한 번도 나오지 않던 문제였고, 이미 사람들이 쓰고 있는 서비스였습니다.
추적
처음엔 어디부터 봐야 할지 몰랐습니다. 다만 한 기능만 죽은 게 아니라 전부 같이 죽었다는 점에서 개별 로직이 아니라 다 같이 쓰는 자원부터 뒤졌습니다.
원인
OSIV가 켜진 상태에서 오래 열려 있는 실시간 연결이 DB 커넥션을 반납하지 않아 기본 커넥션 풀이 고갈된 것이었습니다.
조치
운영 프로필에서 open-in-view를 끄고, 커넥션을 오래 붙잡는 코드가 있으면 스택트레이스가 남도록 누수 감지를 설정했습니다. 해당 설정 파일이 배포 이미지에 포함되지 않는 구조여서 컨테이너 환경변수에도 이중으로 명시하고 배경을 주석으로 남겼습니다.
남긴 것
원인을 찾는 시간보다 무엇을 확인해야 할지조차 몰랐던 시간이 더 길었습니다. 그래서 고치는 것으로 끝내지 않고, 다음에 같은 일이 생기면 어디를 봐야 하는지를 남겨뒀습니다.
비콘 출결 · 운영 환경

출석 시각이 9시간 어긋나 저장됨

증상
로컬에서는 정상이던 출석·세션 시각이 운영에서만 9시간 이르게 저장됐습니다.
원인
운영 컨테이너가 UTC로 기동돼 애플리케이션 기본 타임존이 UTC로 잡혔습니다. 코드에는 아무 문제가 없었고 실행 환경 설정 하나가 달랐을 뿐입니다.
조치
Dockerfile 타임존, 애플리케이션 기본 타임존, 컨테이너 환경변수 세 곳에 고정해 어느 한 곳이 빠져도 어긋나지 않게 했고, 이미 저장된 데이터는 마이그레이션 스크립트로 정정했습니다.
비콘 출결 · 인증

토큰 재발급이 항상 401로 실패

증상
액세스 토큰이 만료되면 재발급을 시도해도 계속 401이 반환돼, 사용자가 매번 다시 로그인해야 했습니다.
원인
재발급 경로가 시큐리티 허용 목록과 JWT 필터 예외 처리 양쪽에서 빠져 있었습니다. 프론트 인터셉터가 붙인 만료 토큰이 필터에서 먼저 걸려 컨트롤러에 도달조차 못 하는 구조였고, 한쪽만 열어서는 해결되지 않는다는 점이 원인 파악을 늦췄습니다.
조치
두 곳 모두에서 재발급 경로를 예외 처리하고, 액세스 토큰 계열과 리프레시 토큰 계열 에러코드를 분리해 클라이언트가 재발급을 시도할 상황인지 재로그인을 요구할 상황인지 응답만으로 구분할 수 있게 정리했습니다.
