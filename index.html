About

2년 만에 서버를 전담하기까지

비전공에서 출발해 2년 만에 서버 전체를 맡는 자리까지 왔습니다. 매 단계마다 결과물을 남겼고, 배운 것은 다음 팀에 그대로 이어 붙였습니다.

  1. 2024.09

    소프트웨어융합학과로 전과, 1년 만에 전공 기초 완성

    자료구조와 알고리즘, 컴퓨터구조, 운영체제, 네트워크, 데이터베이스와 데이터 모델링을 한 해에 몰아 이수했습니다. 데이터베이스는 수업 범위를 넘어 따로 파고들어 SQLD 자격으로 실력을 검증했습니다. 기초를 쌓는 동시에 곧바로 실전으로 나갈 준비를 했습니다.

  2. 2025.03

    학과 코딩 동아리 백엔드 부원 — 가장 어려운 파트를 선택

    여러 파트 중 백엔드를 고른 이유는 가장 복잡해 보였기 때문입니다. 요청 하나가 서버 안에서 어떻게 돌아 응답으로 나오는지를 한 겹씩 파고들었고, 반년 만에 대회 서버를 맡을 수준까지 끌어올렸습니다.

  3. 2025.10

    첫 출전에서 수상 — SUMTECH 해커톤 장려상

    교내 앱개발 경진대회와 SW중심대학 SUMTECH 해커톤에 서버 담당으로 출전했습니다. 1박 2일 안에 기획부터 구현, 발표까지 완주해 Environment 트랙 장려상을 받았습니다. 남은 시간에 맞춰 범위를 다시 잡는 판단이 완성도를 지킨다는 것을 이때 체득했습니다.

  4. 2026.01

    라오스국립대(NUOL) 협력 개발 — 영문 교재 70페이지 제작

    현지 학생들과 한 달간 개발하며 인증과 소셜 로그인을 맡았습니다. 동시에 아키텍처 흐름과 JWT 동작을 코드 단위로 해설한 영문 학습 자료 70여 페이지를 직접 만들어 스터디를 운영했고, 언어도 개발 경험도 다른 팀과 한 달 안에 동작하는 결과물을 완성했습니다.

  5. 2026.03

    동아리 백엔드 운영진 · 멋사대학 14기 선발

    1년 만에 배우는 자리에서 가르치는 자리로 옮겨, 신입 부원 기초 세션과 코드 리뷰를 맡았습니다. 계층 분리·예외 처리·트랜잭션 경계에서 반복되는 지점을 공통 피드백으로 정리해 팀 자산으로 남겼습니다. 같은 해 멋쟁이사자처럼 멋사대학 14기 백엔드 트랙에 선발되어 타 학교 개발자들과 협업했습니다.

  6. 2026.04 —

    산학연계 프로젝트 서버 전담 · 졸업작품 단독 개발

    협력기업 멘토와 지도교수가 참여한 프로젝트에서 서버 전체를 맡아 실제 운영에 배포했고, 운영 중 발생한 전면 장애를 직접 해결했습니다. 같은 기간 졸업작품 서버도 혼자 설계·구현해 커밋 208건을 쌓았습니다.

특정 기능이 아니라 전부 동시에 실패한다는 점에서 개별 로직이 아닌 공통 자원 문제로 즉시 범위를 좁혔고, 커넥션 풀을 확인해 원인을 특정했습니다. 오래 유지되는 실시간 연결이 DB 커넥션을 점유해 여유분이 소진된 구조였습니다.
해결
운영 프로필에서 open-in-view를 비활성화해 장애를 해소하고, 커넥션을 오래 점유하는 코드가 있으면 스택트레이스가 남도록 누수 감지를 설정했습니다. 해당 설정이 배포 이미지에 포함되지 않는 구조까지 파악해 컨테이너 환경변수에 이중으로 명시하고 배경을 주석으로 남겼습니다.
결과
서비스를 정상화했고, 같은 문제가 재발하면 원인 코드를 즉시 지목할 수 있는 상태를 확보했습니다. 배포 방식이 바뀌어도 설정이 유지되도록 안전장치를 이중화했습니다.

시각 오차를 3중 고정으로 차단하고 기존 데이터까지 정정

상황
운영 환경에서만 출석·세션 시각이 9시간 이르게 저장되는 현상을 발견했습니다.
접근
코드가 아니라 실행 환경 차이를 의심해 컨테이너 기동 설정을 확인했고, 컨테이너가 UTC로 떠서 애플리케이션 기본 타임존이 어긋난 것을 원인으로 특정했습니다.
해결
Dockerfile 타임존, 애플리케이션 기본 타임존, 컨테이너 환경변수 세 곳에 고정해 어느 한 곳이 빠져도 어긋나지 않도록 만들고, 이미 저장된 데이터는 마이그레이션 스크립트를 작성해 정정했습니다.
결과
이후 출결 기록의 시각 정확도를 확보했고, 운영 데이터를 손실 없이 되돌렸습니다.

접근
요청이 컨트롤러에 도달하는지부터 역추적해, 재발급 경로가 시큐리티 허용 목록과 JWT 필터 양쪽 모두에서 열려 있어야 동작하는 구조임을 밝혀냈습니다.
해결
두 곳 모두에서 재발급 경로를 예외 처리하고, 액세스 토큰 계열과 리프레시 토큰 계열 에러코드를 분리해 클라이언트가 재발급과 재로그인을 응답만으로 구분할 수 있게 정리했습니다.
결과
